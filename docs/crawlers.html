各來源的性質

  • Yahoo、CNBC、Trading Economics：都是公開網頁或非官方介面，不保證穩定，改版或限流時會失敗。這也是 quotes.json 每個代碼要有多個來源的原因。
  • 證交所 / 櫃買 / FRED / Eurostat：官方開放資料，最穩。
  • 國發會景氣燈號：在 GitHub Actions 上會被 Cloudflare 擋，所以 TW_LIGHT 目前是沿用舊值（stale），本機執行才抓得到。
  • 延遲：Yahoo / CNBC 約 15 分鐘；證交所 mis 是即時；經濟數據本身就是月、季、週頻率。

能不能改成爬取

下表的「實測」是我今天實際連線的結果。

1. 六家央行利率：已完成

已在 world_econ.json 加了 6 個項目（US_RATE、EU_RATE、JP_RATE、CN_RATE、TW_RATE、UK_RATE），沿用現有的經濟數據管線，沒有新增爬蟲。本機強制重跑 fetch-world-econ.js，39 項全部成功，6 個利率的值與先前手寫的一致。
  • 不建議用的來源：FRED 的 IRSTCI01JPM156N 是 OECD 短期利率（實測 1.043，與日本央行政策利率不同）；BOERUKM 資料停在 2017 年。
  • 要等 GitHub Actions 下一次執行並 push 後，線上網站才會讀到 econ.json 裡的新項目。在那之前，線上版的利率卡片會顯示「--」。

2. 美國 12 月升息機率：只能自己估算，不能抓到 CME 的官方數字

CME FedWatch 本身抓不到：我對 CME 的頁面與資料端點測試，兩個都回 403（被擋）。
替代做法：FedWatch 的數字本來就是從「聯邦基金期貨」的價格推出來的。Yahoo 有這些合約的報價，實測：
  • ZQX26.CBT（11 月合約）96.1175 → 隱含利率 3.8825%
  • ZQZ26.CBT（12 月合約）95.98 → 隱含利率 4.02%
粗估：假設 12 月 9 日開會，12 月合約有 9 天在會前、22 天在會後，反推會後利率約 4.076%，比現在的 3.8825% 高約 19 個基點，換算升息 25 基點的機率約 78%。這和卡片上手寫的「約 72%」（10/28）是同一個量級。
限制：這是我自己的估算，不是 CME 的官方數字，會有幾個百分點的差距；開會日期我是憑印象假設的，沒有查證；實作時要抓聯準會公布的會議日程。畫面上要標示「依期貨推算」。

3. 地緣三張卡：數字類可以，「狀態」判斷不行

做法能得到什麼限制
用市場數據當指標已經在 quotes.json 裡的資料：布蘭特 / WTI 原油（美伊、荷莫茲海峽）、黃金與 VIX（風險情緒）、美元兌離岸人民幣（美中）。完全自動，不會過期它們反映市場，不是衝突本身的狀態；要決定每張卡放哪些指標
抓新聞標題每張卡自動顯示「最新一則相關新聞」與時間。候選來源：GDELT DOC API（免費、免金鑰）或新聞 RSS我測了 GDELT：連得到，但它限制每 5 秒只能一次請求，這次沒有取得內容，所以新聞品質我沒有驗證。標題可能離題、重複或是舊聞
自動判斷「休戰中 / 衝突中」—這是需要判斷的編輯內容，單靠爬蟲無法可靠得到。若要自動化，需要接大型語言模型並付費，而且可能判斷錯誤。我不建議

白宮卡片的性質與地緣卡相同。

4. 其他寫死項目

  • 經濟數據備用值：爬蟲已經涵蓋這 13 項，可以刪掉備用值。代價是 econ.json 讀不到時，這些列會顯示「--」而不是舊數字。尚未處理；新加的利率列沒有備用值。
  • 「資料約延遲 15 分鐘」：可以改成依各報價的來源或時間戳記計算，但必要性不高。
  • 交易時段：是固定規則，不建議改成爬取。假日休市沒有行事曆，目前靠「3 小時沒更新」判斷。
  • 旅遊地點：本質是編輯內容，不是行情。
